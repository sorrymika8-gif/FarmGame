# 技能涌现模拟器 — 框架文档

## 一、核心体验

玩家在即时战斗中采集素材，用素材合成道具/药剂，合成结果由 LLM 基于素材语义从正交原子池中推演组合，产出不可预测但逻辑自洽的技能实体。玩家拿着这些技能实体回到即时战斗中，亲手感受涌现效果。

**体验目标：** 3小时内不出现重复且无聊的技能组合。

---

## 二、核心循环

```
战斗 → 采集素材 → 合成道具（LLM推演） → 战斗
```

---

## 三、三层架构

### 1. 效果原子层（底层·程序硬编码）

一套正交的基础参数，保证任何组合都可执行。所有"复合效果"（如眩晕 = 沉默 + 减速100%）不在此层定义，而是由 LLM 在翻译层组合涌现。

### 2. LLM 翻译层（中间·组合推演引擎）

- **输入：** 素材的属性/标签描述
- **输出：** 结构化 JSON（原子参数的子集 + 赋值）
- **角色：** 基于素材语义做创意组合推理，不是随机数生成器
- **文本包装不是重点，** 核心价值在于原子组合的选择与数值生成

### 3. 战斗执行层（上层·即时战斗系统）

程序解析 JSON，生成技能实体投入即时战斗。一切视觉反馈均在此层完成。

---

## 四、正交原子池

所有原子参数严格保证正交性——任何可以由其他原子组合表达的效果（如眩晕、冰冻）不列入原子池，而是作为涌现结果由 LLM 组合产生。

### 4.1 弹道行为类

| 原子 | 取值 | 说明 |
|------|------|------|
| 弹射 | 0 - N 次 | 命中后弹射到其他目标 |
| 追踪 | 0 - 360 度 | 追踪角度，0为不追踪 |
| 穿透 | 0 - N 个 | 可穿透的目标数量 |
| 分裂 | 0 - N 个 | 分裂出的子弹数量 |
| 返回 | 布尔值 | 是否飞回施法者 |
| 吸引/排斥 | -N 到 +N | 负为排斥，正为吸引 |

### 4.2 范围规则类

| 原子 | 取值 | 说明 |
|------|------|------|
| AOE 半径 | 0 - N | 影响范围大小 |
| 形状 | 点/圆/扇形/直线 | 范围形状 |
| 弹道宽度 | 0 - N | 飞行物的宽度 |

### 4.3 数值效果类

| 原子 | 取值 | 说明 |
|------|------|------|
| 直接生命变化 | -N 到 +N | 负为伤害，正为治疗 |
| 持续生命变化 | 每秒 -N 到 +N | 持续伤害/持续治疗 |
| 移速变化 | -N 到 +N | 减速/加速 |
| 攻击力变化 | -N 到 +N | 增伤/减伤 |
| 防御变化 | -N 到 +N | 增防/减防 |

### 4.4 状态类

| 原子 | 取值 | 说明 |
|------|------|------|
| 减速百分比 | 0 - 100% | 移动减速程度 |
| 沉默 | 持续秒数 | 禁用技能释放 |
| 易伤/减伤倍率 | 0.x - N.x | 受到伤害的倍率 |
| 隐身 | 持续秒数 | 不被敌人锁定 |

### 4.5 触发条件类

| 原子 | 取值 | 说明 |
|------|------|------|
| 触发时机 | 立即/被击中时/血量阈值/间隔N秒/击杀时 | 效果何时生效 |

### 4.6 作用目标类

| 原子 | 取值 | 说明 |
|------|------|------|
| 作用目标 | 自身/单体敌人/区域/全体敌人/最近目标 | 效果对谁生效 |

### 4.7 时间类

| 原子 | 取值 | 说明 |
|------|------|------|
| 延迟释放 | 0 - N 秒 | 释放后延迟多久生效 |
| 效果持续时长 | 0 - N 秒 | 效果持续多久 |
| 冷却时间 | 0 - N 秒 | 再次使用的间隔 |

## 五、实体化设计

战斗中所有存在物分为两类，共享同一套原子参数：

- **角色实体：** 玩家、敌人
- **技能实体：** 子弹、投射物、区域效果等

关键设计决策：**子弹/投射物视为独立实体**，拥有自身属性。因此无需额外定义"效果挂载点"维度——所有效果都是实体自身属性的体现。

例：吸引属性挂在技能实体上 → 实体存在期间持续吸引周围敌人（沿途引力效果自然涌现）。

## 六、视觉表现方案

### 核心原则

不为每种合成结果做独立美术资源，而是**为每个原子做一层可叠加的视觉表现**。

### 表现策略

- 追踪 → 弹道轨迹可视化拐弯
- AOE → 扩散圈，半径跟随参数
- 吸引/排斥 → 粒子向心/离心运动
- 分裂 → 一个实体变多个
- 穿透 → 实体不消失，穿过目标
- 减速 → 目标动画播放速率降低
- 持续生命变化 → 目标身上挂持续粒子效果
- 返回 → 弹道反向飞行

### 关键认知

玩家**不需要识别技能的名字**（如"暴风雪"），只需要通过视觉行为**理解技能在做什么**。每层原子视觉语言清晰可辨，组合自动叠加，玩家自然理解。

**资源量与原子数量挂钩，而非与组合数量挂钩。**

## 七、涌现示例

| 原子组合 | 涌现效果 |
|----------|----------|
| 追踪 + 吸引 + AOE | 引力导弹：追踪目标，沿途吸引敌人，命中后范围爆炸 |
| 分裂 + 穿透 + 持续生命变化(负) | 瘟疫散射：分裂为多颗穿透弹，命中目标持续掉血 |
| 返回 + 弹道宽度(大) + 直接生命变化(负) | 回旋巨刃：发出宽幅投射物造成伤害后飞回 |
| 沉默 + 减速100% | 眩晕（组合涌现，非硬编码原子） |
| AOE + 持续生命变化(负) + 减速 | 区域控制：范围内敌人持续掉血且减速 |
| 触发:击杀时 + 分裂 + 追踪 | 连锁猎杀：击杀后分裂出追踪弹飞向其他敌人 |

## 八、已验证结论

| 问题 | 结论 |
|------|------|
| LLM 能否胜任组合推演？ | ✅ 能。结构化JSON输出对当前模型是基础任务 |
| 3小时体验能否不重复？ | ✅ 能。约30个正交原子的组合空间远超需求 |
| "视觉感受差异化"是否可行？ | ✅ 可行。原子驱动视觉叠加，资源量可控 |
| 架构是否存在不可解决的硬伤？ | ✅ 未发现。所有原子均可视化表现 |

## 九、待攻克的落地问题

以下为后续需要逐步解决的工程问题：

1. **LLM 合成流程设计** — Prompt 结构、输入格式（素材描述）、输出格式（JSON Schema）、异常处理
2. **原子池数值平衡** — 各原子参数的合理取值范围、组合后的强度上限控制
3. **即时战斗引擎** — 弹道系统、碰撞检测、实体物理、实体生命周期管理
4. **原子视觉层实现** — 每个原子对应的视觉表现方案、多层叠加的渲染规则
5. **素材系统设计** — 素材的属性/标签体系、采集规则、素材如何影响 LLM 推演倾向
6. **性能与延迟** — LLM 调用延迟对合成体验的影响、缓存策略、离线备选方案
